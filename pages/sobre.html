Sobre o Projeto

O projeto consiste no desenvolvimento de uma solução IoT ponta a ponta capaz de coletar dados ambientais do mundo físico em tempo real e exibi-los em um Dashboard Web interativo.

A solução captura métricas cruciais de temperatura, umidade e qualidade do ar/gás através de microcontroladores e sensores, transmitindo-as instantaneamente via protocolo MQTT/WebSockets para uma interface web responsiva desenvolvida para monitoramento contínuo.

Ferramentas Utilizadas pelo Grupo

Para o desenvolvimento completo do hardware, servidor de mensageria e dashboard web, o grupo utilizou o seguinte ecossistema tecnológico:

  • Hardware & Firmware: Microcontrolador ESP32 Dev Module, Sensor de Temperatura e Umidade DHT11 (GPIO 14), Sensor de Qualidade do Ar MQ-135 (GPIO Analógica) e LEDs de Alerta Físico acionados via GPIO digital. Programado em C/C++ na Arduino IDE.
  • Broker MQTT & Mensageria: Eclipse Mosquitto configurado localmente com suporte a WebSockets (Porta 9001) e porta padrão MQTT (Porta 1883), com registro de publicações em arquivo permanente (mosquitto.log).
  • Front-end Web: HTML5 semântico, CSS3 responsivo e JavaScript ES6 estruturado em arquitetura Single Page Application (SPA).
  • Bibliotecas & Protocolos Web: Biblioteca Paho MQTT via CDN para integração WebSockets e consumo dos dados no navegador, além de suporte ao localStorage para persistência da autenticação.
  • Versionamento & Gestão: Git, GitHub para hospedagem do código e VS Code como ambiente principal de desenvolvimento web.

Metodologia de Trabalho

Adotamos uma abordagem ágil e colaborativa dividida em módulos de engenharia: montagem física da bancada de hardware, programação C++ do microcontrolador, parametrização do broker de mensageria Mosquitto e construção da camada de apresentação web.

O grupo alinhou o envio regular das leituras a cada 3 segundos nos tópicos MQTT estabelecidos, garantindo baixíssima latência entre os alertas acionados pelos LEDs físicos no circuito e a atualização dos cartões visuais no Dashboard Web.

Hardware e Arquitetura do Sistema

A arquitetura é estruturada em três camadas integradas (Coleta, Processamento/Servidor e Apresentação):

  • Coleta & Alerta Físico (ESP32): Leitura periódica do DHT11 e MQ-135 a cada 3 segundos. Acionamento de LEDs de alerta imediato na placa caso a temperatura ultrapasse 28°C, a umidade passe de 56% ou a qualidade do ar exceda 400 PPM.
  • Transmissão & Broker (Mosquitto): Publicação dos dados nos tópicos aulas/professortupi/temperatura, aulas/professortupi/umidade e aulas/professortupi/qualidade_ar via porta 1883, retransmitidos via WebSockets na porta 9001.
  • Interface Web (Dashboard): A aplicação Web utiliza o Paho MQTT em JavaScript para se inscrever nos tópicos e atualizar em tempo real os indicadores gráficos para o usuário.

Processo de Desenvolvimento (Etapas)

O fluxo de trabalho foi executado sequencialmente através das seguintes etapas:

  1. Montagem do Circuito e Firmware: Conexão dos sensores DHT11, MQ-135 e LEDs às GPIOs do ESP32 e programação da lógica de alerta e envio Wi-Fi.
  2. Configuração do Servidor Mosquitto: Edição do mosquitto.conf para liberação de portas (1883/9001), permissões anônimas e ativação dos logs (log_type publish).
  3. Construção da Interface SPA Web: Desenvolvimento do layout responsivo com suporte a navegação por abas ("Sobre o Projeto" e "Dashboard Ao Vivo") e banner do grupo.
  4. Integração WebSockets & LocalStorage: Conexão do Paho MQTT ao cliente web para recepção de payloads JSON e gravação da chave de acesso do professor.
  5. Validação e Testes Finais: Testes de estresse com variação de parâmetros nos sensores para validação simultânea dos LEDs físicos e indicadores web.

Curiosidades do Projeto

  • Duplo Alerta em Tempo Real: Se a temperatura passar de 28°C, o LED físico no ESP32 acende no mesmo milissegundo em que o cartão na tela altera seu estado visual.
  • Rastreabilidade Completa: Com a diretiva log_type publish no Mosquitto, todas as mensagens enviadas pelos sensores ficam salvas no arquivo mosquitto.log no servidor local.
  • Autenticação Persistente: O sistema utiliza localStorage do navegador para guardar a chave de segurança fornecida pelo professor, evitando a necessidade de reautenticação a cada recarga de página.
